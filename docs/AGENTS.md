\# AI開発アシスタント向け 作業ルールおよび開発ガイドライン



本リポジトリ（BrNavi-FandomJP-GUI）のコード調査および改修を行う際は、以下のルールを必ず厳守してください。



\---



\## 1. 最重要禁止事項（テスト作成・実行の禁止）

\* \*\*`tests/` ディレクトリや `pytest` 用のテストコード、モック、ダミーデータは一切作成・実行しないでください。\*\*

\* 実環境での動作確認（実働テスト）は開発者が手動で行います。AI側でテスト環境を構築したり、検証用スクリプトを追加したりする必要はありません。

\* 不要なキャッシュファイル（`\_\_pycache\_\_` 等）をコミット対象に残さないでください。



\## 2. 動的生成データの取り扱いルール（厳守）

\* アプリケーションが実環境・実行時に動的に生成すべきファイル（CSV、キャッシュ、設定・ユーザーデータ等）を、\*\*リポジトリ内に直接作成・配置しないでください。\*\*

\* データの出力形式（スキーマ）や仕様を変更する場合は、\*\*必ず「データ生成ロジック（パーサー・ビルダー側）」と「データ読み込みロジック（利用側）」の両方のソースコードを改修\*\*してください。

\* 生成側と読み込み側で、列名・データ型・区切り文字・エンコーディングの整合性が完全に一致するように実装してください。



\## 3. 作業スコープと実装方針

\* 指示された\*\*本体ソースコードの調査および実装改修のみ\*\*を行ってください。

\* 指示されていないファイルの勝手なリファクタリング、ファイル名の変更、構成の変更は行わないでください。

\* 実装前に、必ず対象となる既存コードおよびアーキテクチャ仕様書（`.md`）を確認し、推測だけでコードを書かないでください。

\* 本アプリケーションは「オフライン／ローカル環境での動作」「高い操作性と低ストレスなUI/UX」を重視して設計されています。既存の設計思想を損なわないよう配慮してください。



\## 4. 作業完了時の報告ルール

\* コードの修正が完了したら、以下の情報のみを簡潔にご報告ください。

&#x20; 1. 変更したファイルの一覧（`git status` の確認結果）

&#x20; 2. 具体的な修正内容と理由の要点（`git diff` に基づく説明）

&#x20; 3. 開発者が実環境で手動テストを行う際に確認すべきポイント
